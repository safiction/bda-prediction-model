# Прогноз неактивности абонентов

Учебный проект: по CDR и обращениям предсказываем отсутствие CDR-активности
в следующие 14 дней у абонентов, активных в предыдущие 14 дней.
Это **14-day inactivity proxy for churn**, косвенный показатель оттока.

## Запуск

Нужен запущенный Docker Desktop с Linux containers. Python и Java на компьютере
устанавливать не требуется. Выполняйте команды из корня проекта.

Исходные CSV должны находиться в `data/raw/{cdr,tickets}/dt=YYYY-MM-DD/`
и `data/late_delivery/{cdr,tickets}/dt=YYYY-MM-DD/`. Нужны все 90 дней:
01.10.2025–29.12.2025, включая разделы из `late_delivery`.

```powershell
docker compose build
docker compose up -d app
```

Откройте [localhost:8501](http://localhost:8501). Интерфейс содержит три раздела:
данные и pipeline, история моделей, прогноз абонента.

## Полная демонстрация

После запуска приложения выполните:

```powershell
docker compose exec -T app python -u -m src.demo
```

Команда проверит аудит, продолжит с сохранённого этапа и последовательно выполнит
обработку, обучение, фиксацию прогнозов и финальную оценку. Повторный запуск
продолжает незавершённый сценарий; выполненные обучения не дублируются.
При ошибке причина находится в `state/jobs/*.log`; после исправления повторите команду.

Для ручного прохождения сначала запустите аудит:
`docker compose exec -T app python -m src.audit`.
Затем проходите те же этапы кнопками в разделе «Данные и pipeline»:

| Часы replay | Действие |
| --- | --- |
| 61 | Подготовить данные; обучить этап 60 |
| 68 | Подготовить данные; обучить этап 67 |
| 75 | Подготовить данные; обучить этап 74 |
| 76 | Зафиксировать прогнозы всех сохранённых моделей |
| 91 | Раскрыть исходы дней 77–90 и сравнить прогнозы |

Дополнительный день нужен для доставки записей по `ingest_ts`.
**CSV за день 91 не нужен.** Обновление страницы не запускает новое задание.
Счётчик файлов может стоять во время дедупликации, записи Parquet и агрегации;
смотрите текущий этап и журнал. Каждый новый cutoff заново обрабатывает доступную
историю, поэтому полный сценарий занимает десятки минут.

## Результаты и повторный запуск

`data/processed/`, `artifacts/` и `state/` подключены с компьютера:
результаты сохраняются при пересоздании контейнера. Исходные CSV подключены только
для чтения; 1 001 повреждённая строка исключается из обработки.

- `artifacts/audit/report.md` — аудит данных.
- `artifacts/runs/` и `artifacts/models/` — обучение, метрики и модели.
- `artifacts/final_predictions/` — неизменяемые прогнозы дня 76 и контрольные суммы.
- `artifacts/final_evaluation/report.md` — итоговая таблица; `comparison.json` — все метрики.
- `state/jobs/` — статусы и журналы заданий.

Остановить приложение после завершения задания: `docker compose stop app`.
Снова открыть с сохранёнными результатами: `docker compose up -d app`.
Для демонстрации с нуля используйте отдельную копию проекта с теми же исходными
CSV и пустыми каталогами `data/processed`, `artifacts`, `state`.

## Проверки

```powershell
docker compose run --rm pipeline -m unittest discover -s tests -v
```

Проверяются временные границы, защита от будущих данных, повторная обработка,
сохранение моделей, очередь заданий, финальные прогнозы и три экрана приложения.

## Код и документация

Простые функции в `src/`: чтение и очистка → Parquet → признаки и метки →
обучение и прогноз → worker и Streamlit. Настройки находятся в `config.json`,
проверки — в `tests/`.

- [План проекта](IMPLEMENTATION_PLAN.md).
- [Архитектура и временные правила](docs/ARCHITECTURE.md).
- [Переиспользование домашних работ и рефакторинг](docs/REFACTORING.md).
- [Результаты полной демонстрации и ограничения](docs/DEMO_RESULTS.md).

Порог классификации — 0.5; активная модель выбирается по validation PR-AUC
(average precision). Окна валидации меняются, абоненты повторяются между снимками:
график метрик не доказывает постоянного улучшения. Результаты характеризуют
неактивность в этом наборе данных и не подтверждают расторжение договора.
